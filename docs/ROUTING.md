# 连线几何与手动布线

本项目把“自动连线”和“用户画线”明确分开：自动连线只是一条连接两个真实端口的直线；只有用户确认的 waypoint 才能产生折点。系统不再维护隐藏的避障路线、车道、线桥、路由证书或后台求解帧。

## 1. 原则与 Owner

`BlockDesignDocument` 是设计事实源：连接端点来自 `source / target`，手动几何只来自可选的 `connection.routing.waypoints`。

`src/layout` 只拥有模块、层级与端口的投影坐标；`src/routing/connectionRoutes.ts` 只把这些坐标投影成可绘制路线；`InterfaceEdge` 只负责显示、选择与手动编辑。Canvas 不保存第二套路由状态。

```text
BlockDesignDocument
├─ source / target ──> Layout 端口锚点 ──> [source, target] ──> 自动直线
└─ routing.waypoints ────────────────────> 恢复正交折线 ─────> 手动路线
```

公开边界只有两类：

- `projectConnectionRoutes(nodes, edges)`：为当前可见布局生成路线。
- `connection.routing.waypoints`：保存用户确认的手动折点，坐标属于连接所在 Level。

投影可以接收上一帧结果作为只读身份缓存：坐标完全相同的线路复用原数组，坐标变化的线路才产生新投影。该缓存不拥有几何事实，也不改变输出；它只避免一次模块编辑让 React 误更新整张图的全部线路。

## 2. 自动直线

没有 `routing.waypoints` 的连接必须满足：

1. 路线恰好包含源端口和目标端口两个点。
2. 移动模块、调整尺寸、移动端口或展开层级时，只重新读取端点坐标。
3. 缩放、Fit、设备像素比和无关属性不能改写路线事实。
4. 交叉、重叠或经过其他模块不会触发隐藏算法；用户可通过选择高亮和手动调整处理具体线路。

布局安装采用 node-first 生命周期。某条线的任一可见端点尚未进入当前布局帧时，该线暂不投影；下一帧端点齐备后自然出现。系统既不伪造临时坐标，也不因单条未就绪线路让整个 Canvas 崩溃。父级循环、缺失端口或缺失连接数据仍属于真实合同错误，必须明确失败。

## 3. 方向与端口

连接语义方向只由 JSON 的 `source → target` 决定，不由卡片相对位置推断。建议输入端口放在左侧、输出端口放在右侧，但四边端口都合法；箭头始终指向语义目标。

端口锚点由 `layout/nodeGeometry` 的同一组尺寸规则和 CSS 变量共同拥有。外侧圆点只用于创建或重连接口；端口文字是唯一的移动入口。文字的透明命中区使用 Canvas inverse zoom 补偿，任何缩放下都保持约 30 个屏幕像素，但不会显示额外抓手。

顶边和底边端口使用垂直文字 chip，向卡片内部展开，避免挤压 Header 或悬在线路上。端口换边或改变 offset 后，所有相连直线立即跟随；松手只提交一次可撤销的端口几何编辑。

## 4. 选择与手动调整

线中不显示标签。端口名提供局部识别，点击线路后由 Properties 展示完整名称、方向、类型、Owner 和 JSON。

自动直线被选中后，在中点显示一个不随缩放变小的菱形命中点。鼠标拖动或键盘方向键会把当前直线物化为正交手动路线；此后：

- 源端和目标端各保留一段沿 Port 朝向伸出的固定短桩；
- 第一次拖动直接创建一条由指针控制的中央横向或纵向主干，避免产生挤在端口旁的细碎折弯；
- 主干方向由两端 Port 朝向优先决定，混合朝向时才按两端距离的主轴决定；

- 空心菱形移动整段；
- 实心方点移动、微调或删除真实折点；
- 端点提示可重连，端点变化后旧 waypoints 被清除；
- Reset to automatic 删除 waypoints，立即恢复两点直线。

拖动预览只属于临时 UI 状态。只有几何真正变化时才提交一次 `connection/route`；单击、Escape、非法重连和窗口失焦都不写 JSON、不污染 Undo / Redo。

手动路线保存前会被规范化：去除重复点和多余共线点，相邻点必须共享 x 或 y。外部 JSON 中不合法的 waypoint 由 Schema / DRC 拒绝，不能在渲染层暗自修成另一份事实。

## 5. 新建与重连预览

从端口拉线时，预览与自动路线使用同一个最小几何规则：`M source L pointer/target`。端口合法性仍由模型层的方向与同 Level 规则判断：

- 绿色端口是合法候选；
- 非法端口给出明确状态，但不提交；
- 释放到合法端口后，正式连接重新读取规范端口锚点，因此预览外框中心与最终锚点允许存在少量 Handle 视觉偏移；
- 无论预览还是提交结果，自动路线都必须只有两个有限且不同的点。

## 6. 验证合同

单元测试覆盖：

- 自动路线始终只有两个点；
- 端点变化仍保持直线；
- 手动 waypoints 恢复为正交路线；
- transient 缺失端点只跳过当前线，不伪造坐标、不崩溃；
- 重复与多余共线点被统一清理。

浏览器测试必须逐条读取 `data-route-points`，检查有限坐标、非零长度、自动两点和手动正交；五层展开与 100 条偏斜连接都检查全部可见线路，而不是抽样。交叉和穿过卡片是当前产品明确接受的视觉结果，不得再以旧避障断言反向定义自动路线。

截图验收至少包含：默认设计全景、线路选中高亮、直线转手动折线、顶 / 底端口 chip，以及低缩放端口文字拖动。人工判断标准很直接：看不清线路、选不中、拖不动或方向误导，均视为问题。

## 7. 与 draw.io 的关系

本项目参考 draw.io 的直接操作原则：对象选择明确、命中区稳定、端点与折点可手动控制、文档事实和临时交互状态分离。但 Architecture Block Studio 不是通用绘图器；它只表达代码模块、端口、类型化接口和层级设计，因此保留更小、更确定的连线合同，不复制 draw.io 文件格式或完整图形库。
